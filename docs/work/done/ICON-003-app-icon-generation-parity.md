# ICON-003: Rebuild app icons from one reference image

- Priority: High
- Affected feature: App icon generation
- Work branch: `feature/app-icon-generation-parity`
- Agent/session: Codex, 2026-09-22
- Depends on: None

## Problem

The app icons currently tracked on `origin/develop` were generated from several
platform-specific input PNGs. Earlier generator work changed their apparent
scale and framing, so it cannot be used as a reliable base for branded and Dev
variants.

## Expected behavior

A repository-owned generator derives every existing production app icon from
one reference PNG while preserving the appearance of the images currently on
`origin/develop`. Once parity is established, the reference can be replaced by
the T-branded artwork, followed by a separate Dev-flavor treatment.

## Acceptance criteria

- One PNG is the only editable raster reference for production app icons.
- A source compositor recreates the platform-specific inputs, then
  `flutter_launcher_icons` recreates Android, iOS, macOS, and Windows assets.
- Every recreated full-color image has less than 1% normalized RGBA pixel
  deviation from the corresponding image on `origin/develop`.
- Monochrome images have the correct dimensions and remain transparent,
  tintable silhouettes; exact historical raster parity is not required.
- Source generation boundaries and monochrome behavior are covered by automated
  tests; the one-time historical pixel comparison is not retained.
- No T branding or Dev-flavor behavior is introduced in the parity checkpoint.

## Progress

- 2026-09-22: Created an isolated branch from `origin/develop` for the parity

  the comparison metric to per-image normalized RGBA mean absolute error.
- 2026-09-22: Recreated the four full-color platform inputs with a maximum

- 2026-09-22: Full test suite passed with 1,254 tests and static analysis found

- 2026-09-22: User reviewed the parity checkpoint and requested removal of the
  historical pixel-equality assertions before commit.
- 2026-09-22: Reverified the source-generation behavior tests, full test suite,
  static analysis, shell syntax, and diff hygiene after removing those
  assertions.

## Handover

- `assets/images/logo.png` is the only editable reference PNG.
- `scripts/generate_icons.sh` first invokes the repository-owned Dart source
  compositor, then invokes the existing `flutter_launcher_icons` CLI. It does
  not use a Flutter-test runner.
- Existing web images are Flutter defaults and were not generated by the
  `origin/develop` launcher configuration, so this checkpoint leaves them
  untouched.
- The T-branded source swap and Dev-flavor behavior are intentionally deferred
  until this parity checkpoint is reviewed.
