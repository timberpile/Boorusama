## Independent conclusions

**C0008:** Live PostScope listens to blacklistTagsProvider and calls setBlacklistedTags on the retained controller. Provider entries preserve their spelling; TagExpression normalizes expression values to lowercase. The controller inserts raw input strings into activeFilters while counts/visibility use normalized expression keys. Uppercase/mixed-case rules can therefore disagree with the filter and popup. Canonicalize through the existing expression representation, preserve operator syntax, prune obsolete keys and preserve intentional disabled states for unchanged rules.

**C0010:** `_currentPageProvider` is global and not auto-disposed. `_TagPages.build` slices from its unbounded current value; clamping happens only after an explicit user page action. A shorter rule list can render no chips while matches exist. The parent key `(controller, auth)` replaces the header but not global provider state. Prefer scoped local page state and clamp against the current list. Test >30 rules, page 2/3, shrink, controller/source replacement and reopening.

**C0013:** setBlacklistedTags awaits an isolate count, then publishes tagCounts before its mounted check and merges active keys without an operation revision. Multiple live changes can complete out of order; lazy initial blacklist loading and awaited filtering also need ownership checks. A fix must prevent stale publication rather than merely triggering another repaint. Test controlled old/new count completions, ingestion overlapping rule changes, disabled controls and disposal. No native scheduling frequency is claimed.

**C0014:** Added widget tests pass `Text('Rules')` or `Text('Temporarily revealed rule')`. They verify shell scrolling/geometry but not controller counts, toggles, rule pagination or live updates. Existing tests should remain and real controls must be exercised; this is a specific coverage gap, not proof of a production error by itself.

**C0022:** The earlier Bookmarks hypothesis is rejected on its actual RawPostScope path because that scope supplies an empty blacklist. However `_CachedFeedGrid` uses ordinary PostScope<Post> with originAndId deduplication and decoded multi-source snapshots. The controller then discards origin and counts/filters with Set<int> of numeric IDs. siteA#42 matching a rule can hide unrelated siteB#42; two matching origins undercount. Both trigger variants must survive deduplication of the finding. Use source identity consistently with existing tracker semantics and preserve isolate-transferability. Do not disable blacklisting for mixed feeds.

**C0023/C0030:** The issue explicitly defers Search redesign and forbids reinterpreting old showPostListConfigHeader as keepTimelineToolbarVisible. Settings tests preserve old values and default new pinning false. Serialization source still needs its final check before closing C0030; no discretionary #115 implementation is authorized.
