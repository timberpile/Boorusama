## AA01-A02-F0004 — Artist previews bypass explicit-media blur and conservative rating handling

- **Kind/severity/confidence/lifecycle:** defect / high / static-confirmed / open.
- **Affected issue/target:** #118 T005. Origin: new preview surface; other pre-existing preview paths are separate.
- **Source/base:** 1d02bef637966999fbd0b72ecb9c6f0e1eedce8a / 422aeae087c1108e655d85d1a3dac25120456cd6.
- **Locations:** [preview selector 12-21](https://github.com/timberpile/Boorusama/blob/1d02bef637966999fbd0b72ecb9c6f0e1eedce8a/lib/boorus/pixiv/following/presentation.dart#L12-L21); [card previews 44-54](https://github.com/timberpile/Boorusama/blob/1d02bef637966999fbd0b72ecb9c6f0e1eedce8a/lib/boorus/pixiv/following/artist_card.dart#L44-L54); [PostGrid uses explicit cover](https://github.com/timberpile/Boorusama/blob/1d02bef637966999fbd0b72ecb9c6f0e1eedce8a/lib/core/posts/listing/src/widgets/post_grid_item.dart#L264-L273); [overlay reads blur preference](https://github.com/timberpile/Boorusama/blob/1d02bef637966999fbd0b72ecb9c6f0e1eedce8a/lib/core/posts/post/src/widgets/explicit_block_overlay.dart#L49-L105); [Pixiv conservative rating parser](https://github.com/timberpile/Boorusama/blob/1d02bef637966999fbd0b72ecb9c6f0e1eedce8a/lib/boorus/pixiv/posts/parser.dart#L263-L275).

### Expected versus observed source behavior

A user enabling explicit-media blur expects Pixiv explicit thumbnails to be covered until reveal, as in standard PostGridItem. The #118 card renders eligible artwork with bare BooruImage and no ExplicitContentBlockOverlay or blur setting check. Artwork with xRestrict=1 on an account with maxRestriction>=1 passes filtering and is displayed uncovered even if blur is enabled. The selector also treats absent xRestrict as 0 and ignores sanityLevel; Pixiv's normal parser classifies sanityLevel>=6 as explicit even if xRestrict is 0/unknown.

### Trigger and reachable failure path

Open Following Artists with blurExplicitMedia enabled and an explicit preview supplied in an artist entry. The account-restriction filter may allow it, then the card loads an uncovered URL. Independently, unknown rating metadata or high sanityLevel can bypass the selector's current conservative restriction test. This is source-demonstrable under these payloads; live incidence is unknown.

### Evidence and safeguards checked

Visible=false, muted, known account xRestrict and foreign initial image hosts are filtered; BooruImage itself respects global disable-media-loading. Those guards do not implement rating-based user blur. Existing grid explicitly wraps images in the cover component.

### Root cause and practical impact

New preview presentation bypasses the shared rating-aware image policy. Explicit content can become visible despite a user-selected safety/blur preference.

### Minimal recommended correction

Evaluate preview rating with the existing Pixiv rating logic (including sanityLevel), fail conservatively on incomplete metadata, and apply the standard explicit overlay or equivalent preview-safe gating according to global media blur. Do not introduce extra artwork requests.

### Suggested local verification and regression checks

Widget tests for blur on/off, xRestrict 0/1/2, sanityLevel>=6, unknown metadata, 0/1/3 previews, Android 320dp and large text; confirm media remains covered until deliberate reveal.

### Assumptions and remaining uncertainty

No live Pixiv response or screenshot was observed. Source shows bypass; frequency and final UI behavior still need device tests.
