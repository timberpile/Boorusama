## Cycle 4 — strict continuation and error-path revisit (2026-10-29T18:16:35.720Z)

Compared all query parameters accepted from Pixiv bookmarks next_url against request-local parameter construction: a return URI must be HTTPS app-api.pixiv.net, no userInfo or fragment, correct path, current user and Public/Private restrict, and a single valid strictly-decreasing numeric max_bookmark_id. Actual subsequent GETs are reconstructed on a fixed API path with redirects disabled; attacker-supplied URLs are not followed. Client malformed response list/entry errors are not translated to empty success. The session's TaskEither maps cancellation to a typed cancelled error, cooldown to RateLimitedError and other exceptions to a generic load failure; page1 refresh cancels old requests and the same page may return a cached result. These checks uphold safety expectations in source, but live Pixiv token, cursor and error integration remain unverified. Separate F0002, F0003, F0005/F0007 and F0008 retain their documented status.
