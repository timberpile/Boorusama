### AA01-A02-F0009 — Shared blacklist pagination state can hide all rule chips

- **Kind / severity / confidence / lifecycle:** defect / medium / static-confirmed / open.
- **Affected:** #114, feature/114-timeline-toolbar, T002. **Origin:** pre-existing on develop (unchanged BlacklistControls file), newly reused inside the anchored toolbar popup.
- **Source/base:** 5bb52794468b172b7d6878fb825b42b00d654675 / 422aeae087c1108e655d85d1a3dac25120456cd6. Verified BlacklistControls blob identical across revisions.
- **Location:** [shared page provider L14](https://github.com/timberpile/Boorusama/blob/5bb52794468b172b7d6878fb825b42b00d654675/lib/core/posts/listing/src/widgets/blacklist_controls.dart#L14); [pagination slice L120-143](https://github.com/timberpile/Boorusama/blob/5bb52794468b172b7d6878fb825b42b00d654675/lib/core/posts/listing/src/widgets/blacklist_controls.dart#L120-L143); [clamp only on user navigation L191-199](https://github.com/timberpile/Boorusama/blob/5bb52794468b172b7d6878fb825b42b00d654675/lib/core/posts/listing/src/widgets/blacklist_controls.dart#L191-L199); [new toolbar popup consumes BlacklistControls L558-580](https://github.com/timberpile/Boorusama/blob/5bb52794468b172b7d6878fb825b42b00d654675/lib/core/posts/listing/src/widgets/post_grid.dart#L558-L580).

#### Expected versus observed source behavior

Every blacklist control should show valid rule chips for its own current set of matches. The private _currentPageProvider is a process-wide StateProvider in the shared Riverpod container rather than per grid/list scope. _TagPages reads its saved page and slices allTags with skip((page-1)*30) without ensuring the page is valid for the new rule count. The clamp in _setPage runs only after a user interacts with pagination.

#### Trigger and reachable failure path

In a grid with 100+ matching blacklist rules, navigate to page 4; then switch to another grid/profile with only 31-60 matching rules and open its horizontal blacklist popup. Both use the same root ProviderScope, so the selected page remains 4. The later grid renders _TagPages because it has more than 30 rules, but skipping 90 items produces no rule chips even though 31-60 rules exist. No reset/clamp on new list or source is present. The page selector itself may offer navigation but cannot restore the missing chips without user action.

#### Evidence and safeguards checked

PostGridConfigurationHeader keys its popup by (controller, auth), preventing reuse of the anchored widget state, but this does not isolate the globally declared Riverpod page provider. The page setter clamps after navigation, not on scope/input replacement. Existing new #114 tests use a static Text Rules and no 31+ rule set, so the issue escapes them. This exact underlying behavior was present before #114; the finding is not attributed to the branch author.

#### Root cause and practical impact

A shared pagination selection survives across unrelated blacklist rule collections. On a shorter matching list, the controls appear empty and users cannot see or toggle their rules on the current page until resetting pagination.

#### Minimal recommended correction

Scope the pagination index to its BlacklistControls instance or owning PostGridController/profile, and clamp or reset it when the rule count/list identity changes. Avoid a global singleton StateProvider for ephemeral UI list position. Keep the fix minimal and preserve the existing horizontal popup and vertical layout.

#### Suggested local verification and regression checks

Widget test opening a 100-rule popup, selecting page 4, switching to a 35-rule grid and asserting 5 visible chips on page 2 or 30 on a reset page 1, with a consistent PageSelector. Recheck shrinking rule count while popup stays open and profile switches; run #114 popup and neighboring grid/filter tests, including Android narrow viewport.

#### Assumptions and remaining uncertainty

The shared provider uses the app's ordinary root ProviderScope; custom nested scopes could isolate individual cases, but the new toolbar popup explicitly uses UncontrolledProviderScope with the current container. The exact PageSelector presentation is untested. Empty chip slice is statically established under the described state.
