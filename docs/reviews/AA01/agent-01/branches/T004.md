## Cycle 4 — refresh/fetch-more concurrency and cancellation

The Grid permits `refresh()` while `_loading` is true, resets `_page=1` before calling the session, and a cancelled prior page-2 fetch can still execute the Grid's `_setPage(_page - 1)` after the refresh reset. ## AA01-A01-F0010 — Pixiv media requests can attach the API bearer to unchecked image hosts

- **Kind / severity / confidence / lifecycle:** risk / high / static-confirmed / open.
- **Affected:** #117, `feature/117-pixiv-favorites`, T004; existing ordinary Pixiv image consumers also inherit the same transport design. Do not attribute the original network-layer behavior to #117's author.
- **Origin:** inherited transport/DTO trust-boundary interaction, exposed as an additional Favorites PostGrid media source.
- **Reviewed head/base:** `e2929259b7725c484d11483d6ea48270079eb2f4` / `422aeae087c1108e655d85d1a3dac25120456cd6`.
- **Source:** [Pixiv DTO image URLs copied without host validation](https://github.com/timberpile/Boorusama/blob/e2929259b7725c484d11483d6ea48270079eb2f4/packages/booru_clients/lib/src/pixiv/types/pixiv_image_urls_dto.dart#L1-L27), [parser into Post URLs](https://github.com/timberpile/Boorusama/blob/e2929259b7725c484d11483d6ea48270079eb2f4/lib/boorus/pixiv/posts/parser.dart#L107-L125), [Grid image loading through BooruImage](https://github.com/timberpile/Boorusama/blob/e2929259b7725c484d11483d6ea48270079eb2f4/lib/core/images/booru_image.dart#L90-L123), [media Dio lookup](https://github.com/timberpile/Boorusama/blob/e2929259b7725c484d11483d6ea48270079eb2f4/lib/core/http/client/src/providers/providers.dart#L102-L116), [Pixiv repository picks authenticated Dio](https://github.com/timberpile/Boorusama/blob/e2929259b7725c484d11483d6ea48270079eb2f4/lib/boorus/pixiv/pixiv_repository.dart#L93-L106), [auth interceptor adds Bearer without destination check](https://github.com/timberpile/Boorusama/blob/e2929259b7725c484d11483d6ea48270079eb2f4/lib/boorus/pixiv/auth/auth_interceptor.dart#L105-L138), [unmodified-host media resolution](https://github.com/timberpile/Boorusama/blob/e2929259b7725c484d11483d6ea48270079eb2f4/lib/core/configs/network/src/types/media_request.dart#L14-L31).

### Expected versus observed source behavior

Pixiv's short-lived app-API access token should only be attached to an explicitly trusted API origin. The new Favorites page converts Pixiv artwork DTOs to ordinary Posts, whose thumbnail/sample/original URLs retain the server-provided strings. The common media renderer obtains `repository.dio(config)`, which is the **authenticated** Pixiv API Dio. `PixivAuthInterceptor.onRequest` unconditionally calls `_applyBearer(options)` for requests, regardless of resolved destination host. The default media resolver preserves any HTTPS/HTTP URL not explicitly overridden.

### Trigger and reachable failure path

A Pixiv API response contains an otherwise valid artwork with an `image_urls.square_medium` or original URL pointing to a third-party host (for example, an unexpected or malicious response value). The standard image-quality selection uses that URL; `BooruImage` passes it to `ExtendedImage.network` with the Pixiv Dio; the interceptor adds `Authorization: Bearer <access token>` on the outgoing request. The URL is not checked to be on an approved Pixiv host in the Favorites post parser or generic media request path. In contrast, #118's *new artist-card preview helper* does explicitly restrict initial image hosts to Pixiv's CDN; this reduces that new surface's external-host exposure but does not repair the shared network layer.

### Evidence and safeguards checked

Source checks covered DTO ingestion, PixivPostRecord and generic Grid-thumbnail selection, media URL resolution, media override mode and `newDio` interceptor registration. Explicit user-configured media host overrides use a separate uncredentialed Dio, but the default **unmodified URL** path uses authenticated Pixiv Dio and has no destination-host guard. Redirect following is disabled for the Pixiv API Dio; this blocks redirect escalation but not the first request to an unchecked absolute URL. The access token is refreshed and short-lived; the long-lived refresh token is not what gets attached.

### Root cause and practical impact

An API/media trust boundary is crossed by reusing the authenticated app-API Dio for arbitrary media URLs. The ordinary expected Pixiv CDN host belongs to the same service, but the code does not guarantee the server-selected URL uses that host. Whether real current Pixiv responses carry third-party URLs is **unverified**; the conditional source path nevertheless allows bearer disclosure if such a value arrives. This is a high-severity conditional security risk, not a claim of observed exfiltration.

### Minimal correction and verification

Separate image fetching from Pixiv bearer authentication or enforce a strict destination allowlist in the bearer interceptor, including retried requests. Use the appropriate image `Referer` without forwarding account credentials to CDN/other media hosts. Add a controlled fake-response test with a foreign `image_urls` host and assert no Authorization header leaves to that host; test allowed Pixiv app-API traffic, real CDN thumbnails, token refresh and redirect handling. Verify that existing Search/Viewer/Downloads retain functioning Pixiv media. No live traffic or tests were executed in this audit.
