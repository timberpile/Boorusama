## AA02-A05-F0004 — Pool source filter accepts unrelated substring-matching hosts

- **Kind / severity / confidence / lifecycle:** `defect` / `medium` / `static-confirmed` / `open`.
- **Affected:** #68, `feature/group-neighboring-series`, T009; newly added Pool branch path. The same underlying substring-style filter already exists for ordinary bookmarked Posts, so the pool change **propagates an existing source-matching weakness to a new object type**, not proof of a novel authentication exploit.
- **Origin:** `interaction / propagated pre-existing behavior` — new typed collection filter mirrors loose legacy URL matching without validating an exact selected host.
- **Primary pinned source:** [Pool selector](https://github.com/timberpile/Boorusama/blob/771082d9c58363348d74b97a2da23732cdd921f0/lib/core/bookmarks/src/types/bookmark_grid_entry.dart#L45-L66); [source-picker host inputs](https://github.com/timberpile/Boorusama/blob/771082d9c58363348d74b97a2da23732cdd921f0/lib/core/bookmarks/src/providers/local_providers.dart#L54-L85); [caller](https://github.com/timberpile/Boorusama/blob/771082d9c58363348d74b97a2da23732cdd921f0/lib/core/bookmarks/src/widgets/bookmark_scroll_view.dart#L147-L164); [existing Post substring comparator](https://github.com/timberpile/Boorusama/blob/771082d9c58363348d74b97a2da23732cdd921f0/lib/core/bookmarks/src/providers/bookmark_group_selectors.dart#L162-L171).
- **Expected:** Selecting source host `example.com` displays only saved references whose canonical source host equals `example.com` (subject to existing supported host/port normalization), never `notexample.com` or `other-example.com` solely because their spelling contains the selected string.
- **Observed code:** `availableBooruUrlsProvider` supplies host strings. `BookmarkScrollView` passes the selected host into `selectBookmarkGridEntries`, which calls `selectPoolBookmarks`. The latter tests `('https://${pool.origin.sourceHost}').contains(selectedBooruUrl)`. With selected `example.com`, a different Pool originating at `notexample.com` satisfies the condition and is included. This is a deterministic string comparison, independent of HTTP or widget timing.
- **Reproduction:** Construct two `PoolBookmark` references with distinct `origin.sourceHost` values `example.com` and `notexample.com`, select source `example.com`, call `selectPoolBookmarks` (or `selectBookmarkGridEntries`) without tag filters. Both pass the current source predicate; only the first should appear. Distinct source-backed Pools may consequently be displayed under the wrong filter and accidentally selected; this does **not** imply that fetching them automatically reuses wrong credentials.
- **Minimal correction:** Compare normalized parsed host identities exactly, with explicit port handling if the source-picker contract requires it. Fix/test the adjacent legacy `Bookmark.sourceUrl.contains(selectedBooruUrl)` behavior consistently, or narrow scope to #68 with a documented follow-up for Posts; never match URLs by arbitrary substring. Preserve selected-site and cross-profile isolation and compare both Pool and Post behavior.
- **Suggested regression:** Test `example.com` versus `notexample.com`, `foo.example.com` (intentional subdomain distinction), same host under HTTPS with optional ports, and source-filter changes for mixed Post+Pool lists. Test selection/card rendering on Android after the final candidate is integrated.
- **Uncertainty:** Actual user occurrence was not observed on a device. The mismatch is statically reproducible for hosts satisfying the string condition. Other #68 paths and the current develop combination remain outside this partial pass.
