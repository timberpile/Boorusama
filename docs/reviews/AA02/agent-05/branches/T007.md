## Implementation summary and paths

Issue #113 requires stopping Load More on complete Related Posts/pools without early exhaustion of incomplete or locally filtered collections. [PostGridController](https://github.com/timberpile/Boorusama/blob/a1bc1d42903861a46e7230349515946bae678357/lib/core/posts/listing/src/widgets/post_grid_controller.dart#L359-L472) now derives continuation from, in order: fetch errors (retry), explicit `hasMore`, `maxPage`, known global `total` with accumulated raw deduplicated items, and finally nonempty source-page response. A nonempty final page is inserted before exhaustion is evaluated. [SinglePagePostListScaffold](https://github.com/timberpile/Boorusama/blob/a1bc1d42903861a46e7230349515946bae678357/lib/core/posts/listing/src/widgets/single_page_post_gird.dart) returns an explicit terminal snapshot. [PoolPostIdsX.fetchPostIds](https://github.com/timberpile/Boorusama/blob/a1bc1d42903861a46e7230349515946bae678357/lib/core/posts/pools/src/types/pool_post_ids.dart) derives pagination from requested ID slices, not the number of matching/accessible posts, and throws on repository errors; the Danbooru pool consumer converts exceptions to `UnknownError` in its TaskEither.
