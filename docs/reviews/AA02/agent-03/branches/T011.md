## Findings

### AA02-A03-F0001 — Unimplemented share backend escapes error feedback

- Kind / severity / confidence / lifecycle: **defect / low / static-confirmed / open**
- Affected: #95, `feature/95-artist-links`, T011
- Origin: introduced in this branch
- Reviewed head/base: `7fa4e4f7fadd28cdf332c6855ac18e4fd28b3e9a` / `422aeae087c1108e655d85d1a3dac25120456cd6`
- Location: `lib/core/posts/links/share_artist_link_button.dart`, `_ArtistLinkShareButtonState._share`, lines 36–61
- Source: [pinned artist share implementation](https://github.com/timberpile/Boorusama/blob/7fa4e4f7fadd28cdf332c6855ac18e4fd28b3e9a/lib/core/posts/links/share_artist_link_button.dart#L36-L61); [existing search share handler](https://github.com/timberpile/Boorusama/blob/7fa4e4f7fadd28cdf332c6855ac18e4fd28b3e9a/lib/core/posts/links/share_search_link_button.dart#L102-L115)

#### Expected versus observed source behavior

Unsupported/unimplemented native share dispatch should produce the same contained error feedback as the existing search .bslink sharing path. The new artist handler catches only `Exception`; Dart's `UnimplementedError` is an `Error`, therefore bypasses that catch. The existing search file sharing explicitly catches `on UnimplementedError`.

#### Trigger and reachable failure path

Tap the enabled artist share button; `BoorusamaLinkFileShare.share` awaits `ShareActionAdapter.shareFiles`. If the adapter/plugin throws `UnimplementedError` (including a platform registration/capability mismatch), the Error propagates through the callback without a user-facing failure toast. `finally` does restore `_sharing`, so this is not a stuck-spinner bug. This is a conditional reachable source path, not a claim it occurred on a device.

#### Evidence and safeguards checked

Checked the enabling `canShareMedia` predicate, `_sharing` in-flight guard, underlying document-share adapter, and old search-share handler. Capability check ordinarily prevents unsupported platforms but does not guarantee a registered native plugin cannot throw. Other `Exception` failures are already contained.

#### Root cause and practical impact

The new share handler omitted the explicit `UnimplementedError` catch used by the equivalent existing action. A failed handoff becomes an unhandled asynchronous Flutter error instead of an error toast for affected devices/platform states.

#### Minimal recommended correction

Catch `on UnimplementedError` in `_share` with the same mounted-guarded failure toast as `on Exception`; do not broadly catch all `Error` types. Add a widget test where the injected share adapter throws `UnimplementedError` and assert no escaping test exception and one visible failure indication.

#### Suggested local verification and regression checks

Run artist/share/search link widget suites using FVM. Exercise an injected unsupported adapter plus a successful and a cancelled share; confirm pending disable and recovery.

#### Assumptions and remaining uncertainty

Actual native plugin reachability varies by supported platform and installation. Severity low because the path requires an uncommon adapter failure. Source-level Error type and catch mismatch are demonstrable; not reproduced on Android.
