## Findings

### AA02-A03-F0004 — Pixiv Following previews treat unrated work as all-ages

- Kind / severity / confidence / lifecycle: **risk / medium / high-confidence / open**
- Affected #118 / `feature/118-pixiv-following-artists` / T021
- Origin: introduced in this branch; content-rating gate differs from pre-existing shared Pixiv rating mapper
- Reviewed head/base: `1d02bef637966999fbd0b72ecb9c6f0e1eedce8a` / `422aeae087c1108e655d85d1a3dac25120456cd6`
- Location: `lib/boorus/pixiv/following/presentation.dart`, `pixivFollowingPreviewUrls` lines 12–24; contrast with `lib/boorus/pixiv/posts/parser.dart`, `pixivRatingFrom` and DTO `sanityLevel`.
- Pinned source: [following preview predicate](https://github.com/timberpile/Boorusama/blob/1d02bef637966999fbd0b72ecb9c6f0e1eedce8a/lib/boorus/pixiv/following/presentation.dart#L12-L24); [Pixiv rating mapping](https://github.com/timberpile/Boorusama/blob/1d02bef637966999fbd0b72ecb9c6f0e1eedce8a/lib/boorus/pixiv/posts/parser.dart#L251-L274); [nullable DTO signals](https://github.com/timberpile/Boorusama/blob/1d02bef637966999fbd0b72ecb9c6f0e1eedce8a/packages/booru_clients/lib/src/pixiv/types/pixiv_illust_dto.dart#L1-L77).

#### Expected versus observed source behavior

The preview is supposed to respect account content restriction. The DTO has two rating signals, `x_restrict` (nullable R18 flag) and `sanity_level` (nullable explicitness). The main Pixiv parser classifies `sanity_level >= 6` as explicit even when `x_restrict` is missing or 0. In contrast, Following's preview predicate checks only `(artwork.xRestrict ?? 0) <= maxRestriction`. For an account with `maxRestriction=0`, a valid artwork with `x_restrict=null, sanity_level=6, visible=true` and a valid image URL **passes** and gets a preview, although the established mapper treats it as explicit.

#### Trigger and reachable failure path

An account whose stored `PixivExtraData.xRestrict` is absent or zero opens Following Artists; a service-supplied artwork preview has no x_restrict but sanity_level=6. The client parses nullable DTO data; preview predicate accepts it as unrestricted and `BooruImage` requests its supplied pximg URL. A service-provided image may be shown despite the account's all-ages setting. No additional artwork fetch is initiated, but the supplied image is displayed.

#### Evidence and safeguards checked

The card correctly rejects foreign image hosts, `visible=false`, muted posts, and known `xRestrict>0`; current authored tests cover only explicit x_restrict=1. They do not test missing x_restrict with restrictive sanityLevel. `PixivIllustDto` intentionally allows nullable metadata for forward compatibility. The main post parser explicitly cautions that unknown x_restrict alone must not be treated as safe. No evidence that Pixiv's actual following response frequently contains this contradictory/missing rating combination, hence kind **risk** and confidence **high-confidence**, not executed/confirmed device exposure.

#### Root cause and practical impact

Duplicated simplified rating eligibility check treats unknown explicitness as safe, potentially displaying an R18 thumbnail for an all-ages account. The impact depends on actual server response and account token restrictions; no claim of proven live content leakage.

#### Minimal recommended correction

Reuse the engine's existing conservative `pixivRatingFrom` signals or a shared Pixiv preview eligibility predicate, and explicitly decide conservative behavior for missing rating metadata and account xRestrict. Avoid assuming a missing xRestrict implies all-ages. Keep source-supplied preview-only rule and CDN host validation unchanged.

#### Suggested local verification and regression checks

Add a unit test for sanityLevel=6 with xRestrict null/0 and account maxRestriction=0, another with both values unrestricted, and accepted R18 for account xRestrict=1. Check actual API response combinations and local Android preview. Validate unknown metadata and R18G boundaries across both profile settings and shared Pixiv rating policy.

#### Assumptions and remaining uncertainty

Actual server filtering may already exclude these artworks from responses to an all-ages account; this review does not assert that a real account can trigger exposure. The source predicate inconsistency is factual and merits conservative remediation.
