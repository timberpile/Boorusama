## Issue and implemented behavior

Adds a profile-specific Pixiv Following Artists tool to existing engine navigation without replacing shared Following Topics, fetching the logged-in user's Public/Private followed artists via verified fixed endpoint and offset pagination. Artist cards use returned user ID, name/account, avatar and up to three already-provided artwork previews with adult-content filtering; no extra artwork requests. Tapping the card opens regular Search in the exact originating Pixiv profile with a `user:<numeric-id>` query. No Follow/Unfollow editing or locally stored subscription state is implemented. An unverified All filter is deliberately excluded.

## Findings

**No actionable defect established from inspected source paths at this pinned revision.** Unlike #117, this feature does **not** depend on the shared PostGrid's nonempty-page heuristic: its own manual Load More UI continues while a validated source offset exists, including an empty first list. A failed later request leaves the previously fetched artist list visible, offers Retry using the same offset, and does not show an empty-success state. Refresh and profile/filter changes cancel obsolete pagination work. Requests are pinned to the Pixiv App API domain, not server-supplied next URLs; returned previews are limited to known Pixiv image hosts and filtered for content-restriction level.

No UI/device or network tests were executed to confirm the actual API and authorization behavior. A valid source-returned response could still differ in structure and cause a non-empty failure state; treat that as a live acceptance gap, not a proven defect from this code alone.
