## Intent and scope

The Follow destination dialog reused transient checkbox state when entering another folder with a row at the same index. The issue requires immediately correct identity-bound checkbox values, preserving pending selections across folders and normal user toggle animation.

**Reviewed changed files** (the old branch handoff was not opened):
- `lib/core/search/following_topics/src/widgets/follow_topic_folder_picker.dart`: `CheckboxRangeItem` gets a stable `ValueKey<(String?,)>` for Home and each actual folder ID (lines 168–185), all other selection logic unchanged.
- `test/follow_destination_identity_test.dart`: two scale/inset variants covering first-frame element replacement after entering a child, the non-animated initial state, normal toggle element retention, back/forward selection restoration and resulting chosen folder IDs.

**Reviewed surrounding execution paths:** `lib/core/selection/checkbox_range_selection.dart` controller reindex/reconcile logic, `CheckboxRangeItem` inner `SelectableBuilder(key: ValueKey(index))`, folder navigation and the picker dialog's `_selected` set, parent/child traversal and asynchronous folder creation.

## Findings

**No actionable defect identified in this static pass.** Adding keys to the *outer* `CheckboxRangeItem` ensures Flutter does not reuse the same State subtree for unrelated folder IDs even when both map to the same positional `SelectableBuilder` index. The record-valued key is structurally comparable across rebuilds, so toggling the same destination retains its element/animation state. The picker stores `_selected` outside the visible folder list, and the shared controller explicitly preserves selection outside current entries. This is not a runtime proof.
