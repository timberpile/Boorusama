## Finding AA02-A04-F0001

### AA02-A04-F0001 — In-place live-feed extension is invisible to the preloader's refresh guard

- **Kind / severity / confidence / lifecycle:** defect / medium / static-confirmed / open.
- **Affected:** #53, T001; shared mixed viewer (potentially any engine using live-feed pagination).
- **Origin:** pre-existing refresh omission, with a newly added identity-only guard failing to cover it. The merge-base version has no `didUpdateWidget` refresh at all, so the underlying inability to react to appended posts should **not** be attributed entirely to this branch.
- **Reviewed target and base:** `f7eba53fec0bc0369a9c3e84a8931353c0a8a3cf` / `6875e0ce778aecfb2b83780c2185ce9273a9b2cc`.
- **Location:** `lib/core/posts/details/src/widgets/post_details_image_preloader.dart`, `_MixedPostDetailsImagePreloaderState.didUpdateWidget`, lines 77–81; corroborating `_MixedPostDetailsPageState._onLiveSourceChanged`, lines 117–127; and `PostDetailsScope.build`, lines 149–155.
- **Pinned source:** [refresh guard](https://github.com/timberpile/Boorusama/blob/f7eba53fec0bc0369a9c3e84a8931353c0a8a3cf/lib/core/posts/details/src/widgets/post_details_image_preloader.dart#L77-L81), [in-place append](https://github.com/timberpile/Boorusama/blob/f7eba53fec0bc0369a9c3e84a8931353c0a8a3cf/lib/core/posts/details/src/widgets/mixed_post_details_page.dart#L117-L127), [list passed unchanged](https://github.com/timberpile/Boorusama/blob/f7eba53fec0bc0369a9c3e84a8931353c0a8a3cf/lib/core/posts/details/src/widgets/post_details_scope.dart#L149-L161).

#### Expected versus observed source behavior

When a live feed fetches more posts while the viewer stays on its last visible post, the preloader should refresh its bounded next-neighbor window and queue newly available metadata/images. The current guard refreshes only if the list **object** is replaced, not if its contents change.

#### Trigger and reachable failure path

`MixedPostDetailsPage` retains `_posts` as a final mutable list. `_onLiveSourceChanged` calls `_posts.addAll(added)` and triggers `setState`. The same list reference passes through `PostDetailsScope` to `MixedPostDetailsImagePreloader`. Its `didUpdateWidget` checks `!identical(oldWidget.posts, widget.posts)`, which stays false. While the page index and dependencies remain unchanged, neither the current-page listener nor the new guard recomputes the preload plan. Newly appended neighbors therefore receive no speculative metadata/image preload until another trigger, such as a page change.

#### Evidence and safeguards checked

The new `onResolved` callback only runs for already queued metadata, and no new queue requests are generated from the append. The existing `PostDetailsScope.build` updates the total-page counter, but this does not itself notify the preloader's page listener. An actual swipe can recover, which makes this a timing/performance defect rather than permanent failure to load the image.

#### Root cause and practical impact

List identity is used as a mutation/version signal, although the live source mutates that list in place. On Realbooru, the preloader can miss its useful advance window immediately after pagination, leaving thumbnail-to-display transitions slower than intended.

#### Minimal recommended correction

Track an independent prior list length and bounded-window post identities (or propagate a monotonic content-revision signal) inside preloader state; schedule a refresh when the revision changes. Comparing `oldWidget.posts.length` with `widget.posts.length` is **not** sufficient because both may reference the already-mutated object. Keep updates coalesced and bounded.

#### Suggested local verification and regression checks

Widget test: render the mixed viewer at the end of a mutable list, append a new eligible post through the live-source notifier without changing the current page, pump, and assert its metadata/thumbnail preload is scheduled exactly once; check profile grouping, no original-only URL, and cancellation on route inactivity. Follow with Realbooru on-device swipes and image/network-cache diagnostics.

#### Assumptions and remaining uncertainty

The visual impact varies with network/cache latency. A separate unobserved consumer might already download the new neighbor; none in the inspected preloader path invalidates this finding. This is static source analysis, **not** reproduced on device.
