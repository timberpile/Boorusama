## Intended behavior and implementation

The approved design `docs/designs/2026-10-29-viewer-toolbar-layout.md` chooses physical placement instead of priority. A global nullable JSON settings override leaves old viewers unchanged until user opts in. The editor uses live preview, drag-and-drop and accessible controls, More transfers, explicit slot replacement on full toolbar, Apply/Reset and rollback on save errors. Engine-specific action availability is projected onto a persisted action order, never rewriting saved positions. At narrow widths the visible **center** action run remains and outer actions go to the far-right More popup.

## Findings

**No independently actionable static defect established in the inspected scope at this pinned revision.** Capacity calculation reserves the far-right 48dp More target and bounded gaps. Projecting only currently available action IDs does not mutate global preferences; an unavailable favorite/vote can return in its saved position later. Even an explicit empty toolbar is valid. Legacy/default engine order remains when settings override is null, and malformed settings recover to legacy. More uses the original action widget/menu variants and enclosing post's Riverpod container, not the global default profile.

The approved design explicitly makes this a **trial requiring manual UX acceptance**, so source and mock/widget tests alone cannot qualify the five-action limit or More/drag affordances on real devices. No source defect is inferred solely from the unexecuted manual gate.
