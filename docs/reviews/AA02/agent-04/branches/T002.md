## Finding AA02-A04-F0002

### AA02-A04-F0002 — Original viewer quality renders no image when original is unknown but a sample exists

- **Kind / severity / confidence / lifecycle:** defect / medium / static-confirmed / open.
- **Affected:** #76, T002, Realbooru `Original` viewer-quality mode; the default shared resolver can affect other engines that emit unknown originals.
- **Origin:** introduced on this branch by changing unavailable originals from the known displayed URL to empty, while leaving a consumer that expects a nonempty original; observed `develop` retains the relevant behavior.
- **Reviewed source:** `b8895d1e142c6b0e86b4a1f7359e7288ecc6fee5` and `6875e0ce778aecfb2b83780c2185ce9273a9b2cc`; persisted `develop` snapshot `84df0c2de6cf8fe0177c49babb3fb0eee880f866`.
- **Location:** `packages/booru_clients/lib/src/gelbooru_v2/parsers/rb_parsers.dart` lines 82–92 and 134–140; `lib/core/posts/details/src/types/media_url_resolver.dart` lines 33–42; `lib/core/posts/details/src/widgets/post_details_image.dart` lines 146–163.

#### Expected versus observed source behavior

The parser correctly refuses to mislabel a sample as verified original, but a user configured to show `Original` should still see the available sample if the actual original is unknown. Instead, `Original` quality returns an empty media URL and the viewer renders `KurumiImagePlaceholder`.

#### Trigger and reachable failure path

Realbooru detail HTML displays a sample under `/samples/` but has no trusted Original control, or has an invalid/ambiguous Original URL. `parseRbImageMetadata` returns `originalUrl: null`; `parseRbPostHtml` assigns `fileUrl: ''` and still assigns `sampleUrl: displayedUrl`. `gelbooruV2PostDtoToGelbooruPost` preserves an empty `originalImageUrl`. `DefaultMediaUrlResolver.resolveMediaUrl` chooses `post.originalImageUrl` whenever `config.imageDetaisQuality == 'original'`, without checking emptiness. `RawPostDetailsImage` explicitly shows a placeholder for `imageUrl.isEmpty`.

#### Evidence and safeguards checked

The test `rb_original_metadata_test.dart` specifically asserts an absent Original gives `fileUrl == ''`, proving this input is supported. `Post.hasFullView` checks an original exists, protecting explicit zoom-to-original, but **does not** protect the independently configured default viewer-quality selection. The default sample-quality mode works, which can hide this regression during basic checks. An observed `develop` version retained the same empty-original mapping and the shared resolver switch, so the concern is not merely historical.

#### Root cause and practical impact

Parser truthfulness and renderer fallback are coupled incorrectly: an unknown original needs a nullable/empty model value, but should not remove the valid on-screen sample when an Original preference is selected. Users can lose the displayed image entirely for Realbooru pages with no recoverable Original URL.

#### Minimal recommended correction

Keep `originalImageUrl` empty when unknown. In the media-quality resolver, for `Original`, select a nonempty original only; otherwise fall back to the known sample, then optionally thumbnail, preserving explicit knowledge semantics and handling video/GIF separately. Consider whether downstream image-sharing and download actions also require graceful handling of missing originals; do not synthetically designate a sample URL as an original.

#### Suggested local verification and regression checks

Create a Realbooru full-detail parser fixture with a valid sample and no trusted Original control. Verify `Original` viewer preference still provides the sample URL, whereas a known Original uses its distinct URL. Widget-test resulting `RawPostDetailsImage` rendering, repeat on Android with live Realbooru, and ensure snapshots, prefetch, download/share paths are consistent.

#### Assumptions and remaining uncertainty

Reproduction is based on executable source-path conditions and matching parser tests, **not a recorded live-device failure**. Actual frequency depends on Realbooru HTML and viewer preferences.
