## A. Replace 'Definition Updated' with a blue UNSEEN badge (approved UX contract)

- Remove the existing generic 'Definition Updated' icon, informational dialog, and user-facing acknowledgement affordance from received Following Topic cards, Folder cards, opened Folder headers, and Feed surfaces. Ordinary incoming definition synchronization remains automatic.
- Show an additional **blue UNSEEN badge** on received Topics, next to the existing New Posts badge when both apply. They are independent indicators. Do not show this badge on ordinary local Topics.
- **First subscription:** every Topic received in the initial subscribed collection is UNSEEN, including Topics in nested Folders. A directly received Topic is also initially UNSEEN.
- A Topic is UNSEEN when its current definition digest is not its receiver-local seen definition digest. Reusing `FollowingMirrorOwner.definitionDigest` / `seenDefinitionDigest` is approved; re-showing UNSEEN after rename/query/other definition changes is acceptable.
- A received Folder shows a blue UNSEEN badge iff at least one canonical Topic in its recursive subtree is currently UNSEEN. Derive this from descendant Topic receipts, not the Folder's own definition digest (which might remain changed after individual Topics have been viewed). The same state propagates to relevant ancestor Folder cards without duplicate counting.
- **Open Topic:** acknowledge that Topic's captured current digest only after successful navigation to its Topic/search content. A missing profile, unsupported source, failed navigation, or disabled card must not clear the badge.
- **Open Folder Feed:** after successful entry, acknowledge the captured current digests of all included Topics, including nested descendants. Merely entering the Folder browser, refreshing/synchronizing, opening menus, or seeing previews must not acknowledge them. Independently subscribed canonical appearances share receiver-local Topic state.
- Badge/acknowledgement state persists across application restarts, background updates, refreshes, and unrelated publication edits. Do not reset existing previously acknowledged Topics merely because this UI changes.
- Preserve the existing New Posts badge and unread-post behavior without conflating it with newly received Topic definitions. Keep receiver-local acknowledgements off the signed publisher-owned definition/protocol.
- Guard against races: use the captured definition digest when acknowledging so a later incoming revision cannot be accidentally marked seen. Reuse existing compare/ack service code where appropriate.

**Required verification:** first subscribe with nested Topics; new Topic added later; Topic rename/query update; simultaneous blue UNSEEN + Post NEW badges; open one Topic and recalculate parent badges; open a parent or nested Folder Feed; only open Folder browser; stale digest during synchronization; restarts; empty Folders; duplicate/overlapping subscribed roots; missing-profile navigation; narrow width and enlarged text. Block only *new* individual Topic publications. Do not break old catalog/receive compatibility.
