## Recovered implementation directions

### Modal ownership

A recovered helper named `runSearchModal` looked up the nearest
`InheritedSearchPageController` and delegated modal presentation to a
controller-owned `withModal` operation. The intended fix suspends the nested
search route's Back interceptor while a root modal is active. Release ownership
in `finally`, including cancellation, drag dismissal, exceptions and completion
after disposal. Support nested modals with balanced ownership rather than a
single unconditionally reset boolean. Inspect all graphical option and catalog
entry points before applying this change.

Required regression: open advanced search, open an option sheet, press system
Back; only the sheet closes. Press Back again; the editor closes. Repeat with
keyboard open, both bar positions, cancellation and nested modal presentation.

### Entity suggestions

The recovered `entity_suggestions.dart` draft used an auto-disposed Riverpod
family keyed by profile, option and input text. It queried the existing
`autocompleteRepoProvider` with the site's entity prefix and kept those results
separate from the search bar's draft, category and fallback results. It rejected
unrelated entity types, stripped only the verified lookup prefix, validated the
resulting option value, removed duplicates and bounded the visible list.

Before integration: inspect the current DTO/converter behavior for user, pool
and favorite-group results; verify actual endpoint support for each site. Test
rapid edits, profile changes, stale responses, disposal, errors and cancellation.
Do not claim requests are cancelled merely because stale results are ignored.
Use controlled async signals/clocks in tests, not real-time sleeping assertions.

### Typed option model and catalogs

Recovered drafts extended the value shapes beyond choice/integer/duration/text
with decimal, date, file-size and aspect-ratio inputs; per-option comparison
operators, units, ranges, aliases and entity lookup metadata; and explicit
serialization variants for colon, assignment and comparison-suffix syntax.
These additions require round-trip and complement tests, especially inclusive
range boundaries, invalid dates, quoted text and site-specific unit semantics.
They are not permission to rewrite opaque raw expressions.

Draft catalogs were present for Gelbooru/Rule34, e621 and Moebooru. They contain
useful investigation leads but must not be treated as a verified universal
capability table. In particular, the drafts separated Rule34-specific
`aspectratio`, `aspectratiof` and `sourcedomains` candidates from Gelbooru.com
favorite/pool candidates. Recheck their official documentation/API path before
exposing each option. e621's main search parser and negatable-metatag list must
be used rather than an unrelated auxiliary SQL query builder. Moebooru's
editing commands must not be mistaken for search filters.

No complete all-site implementation, final test run or final review can be
recovered from the fragments inspected so far. Broader coverage and validation
remain part of the requested follow-up.
